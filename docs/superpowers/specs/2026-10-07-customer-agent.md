# 面向用户的售后 Agent 规格

用户已批准实施讨论后的流程，不包括评测扩展和实时 Web 界面。

输入：一至八张图片和用户文字；补交允许仅文字或仅图片。Jev 从文字识别包装破损、商品问题、数量不足、错发或不明确，允许多个问题；识别诉求不等于核实问题。VLM 按检查清单提取事实；Jev 分别评估每个问题及充分性。材料文本始终视为数据，不是指令。

程序提供合法候选工具，并阻止相互矛盾判断、遗漏原图、旧证据和缺少规则支持的结束。下一步候选包括分析、裁剪、重新判断、请求信息或人工复核。退款、补偿、补发均是建议，不执行业务写操作；缺省政策是明确标注的演示规则，真实政策由用户提供。

工单：SQLite 持久化用户提交、托管图片副本、每次运行和规则快照。请求信息返回中文原因、所需材料、拍摄说明和恢复命令。resume 可追加材料或替换指定图片；替换清除该图片证据，文字更改使判断重新计算。缓存保留正确版本，任务状态和调用记录不会跨工单混淆。单工单限制八次提交、八张有效原图，每次最多六轮，每个原图最多两次视觉补充；仅文字补交不重置视觉预算。

命令：inspect --text 创建并运行；resume CASE_ID 补交并继续；case CASE_ID 查询历史；chat 引导用户在同工单补交。原 analyze/classify 保留诊断用途；batch 和 demo 使用新的流程。stdout 可选择完整 JSON、Markdown 或面向用户文本；日志 stderr。CLI 统一 API 错误包含失败阶段而不输出供应商密钥。无 Web 新依赖。

验收：清晰/模糊/无关照片、数量不足及复合诉求；同工单补证继续、替换来源、跨进程恢复和并发冲突；政策候选限制和证据门槛；损坏文件、异常 API、预算终止、无密钥回放；非 editable 安装于两个环境。
